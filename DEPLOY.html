Déploiement SendProColis

Web, API et fichiers uploadés servis derrière une seule adresse, avec HTTPS automatique via Caddy. Trois conteneurs Docker, aucune configuration TLS manuelle.

sendprocolis-caddy sendprocolis-api sendprocolis-postgres

◎Vue d'ensemble

Déploiement domaine unique (path-based) : une seule adresse sert la SPA React, l'API Express et les médias. Caddy gère le reverse-proxy et le certificat TLS.

Internet ──443/80──▶ Caddy ──┬── / SPA React (statique) ├── /api/* ─▶ API (Express) └── /uploads/* ─▶ API (médias) API ─▶ Postgres (réseau interne, aucun port exposé)
🔒
Seul Caddy est exposé publiquement (ports 80/443). L'API et Postgres ne sont joignables que sur le réseau interne Docker.

1DNS

Créer un enregistrement A pointant vers l'IP publique du VPS :

TypeNomValeur
Asendprocolis.exemple.com<IP du VPS>
⚠️
Le certificat TLS ne sera émis que si le DNS est propagé et que les ports 80/443 sont ouverts.

2Préparer le VPS (Debian vierge)

Connecté en SSH sur le VPS, installer Docker et le plugin Compose depuis le dépôt officiel :

# --- Docker + plugin compose (dépôt officiel) ---
sudo apt-get update
sudo apt-get install -y ca-certificates curl git ufw
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/debian/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] \
  https://download.docker.com/linux/debian $(. /etc/os-release && echo $VERSION_CODENAME) stable" \
  | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null
sudo apt-get update
sudo apt-get install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

# Lancer docker sans sudo (se reconnecter après)
sudo usermod -aG docker $USER

# --- Pare-feu : n'ouvrir que SSH + HTTP + HTTPS ---
# Autoriser le 22/tcp AVANT le enable, sinon la session SSH est coupée.
sudo ufw allow 22/tcp
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw --force enable

Vérifier : docker --version && docker compose version

3Cloner les deux repos côte à côte

Le docker-compose.yml (dans SendProColis-Web) construit l'API depuis le repo voisin ../SendProColis-Api. Les deux doivent être au même niveau :

mkdir -p ~/sendprocolis && cd ~/sendprocolis
git clone <url-SendProColis-Web>   SendProColis-Web
git clone <url-SendProColis-Api>   SendProColis-Api
cd SendProColis-Web

Arborescence attendue :

~/sendprocolis/
├── SendProColis-Web/   ← lancer docker compose ICI
└── SendProColis-Api/

4Configurer les secrets

  1. Copier le modèle : 
    cd ~/sendprocolis/SendProColis-Web
cp .env.production.example .env
  2. Générer les secrets : 
    echo "POSTGRES_PASSWORD=$(openssl rand -hex 24)"   # hex = URL-safe
echo "JWT_ACCESS_SECRET=$(openssl rand -hex 32)"
echo "JWT_REFRESH_SECRET=$(openssl rand -hex 32)"
    ⚠️
    Générer le mot de passe Postgres en hexadécimal (-hex), pas en -base64 : les caractères / + = du base64 cassent le parsing de la DATABASE_URL côté API.
  3. Renseigner .env avec nano .env : 
    DOMAIN=sendprocolis.exemple.com
TLS_EMAIL=fc@futurschoisis.net
POSTGRES_PASSWORD=...
JWT_ACCESS_SECRET=...
JWT_REFRESH_SECRET=...
💡
PUBLIC_BASE_URL, CORS_ORIGIN et l'URL d'API du front (VITE_API_BASE_URL) sont dérivés automatiquement de DOMAIN par le compose — rien d'autre à renseigner.

5Build & démarrage

cd ~/sendprocolis/SendProColis-Web
docker compose build          # build SPA + image API (quelques minutes)
docker compose up -d          # démarre caddy + api + postgres

# Les migrations Prisma s'exécutent automatiquement au démarrage de l'API.

docker compose ps             # tout doit être running / healthy
docker compose logs -f caddy  # vérifier l'émission du certificat TLS

Caddy obtient le certificat au premier accès HTTPS. Tester :

curl -I https://sendprocolis.exemple.com/api/v1/health   # 200 attendu

Puis ouvrir https://sendprocolis.exemple.com dans un navigateur.

(Optionnel) Peupler la base avec les comptes de test

⚠️
Le seed crée les utilisateurs de démo (PIN 123456). À ne pas exécuter sur une vraie production.
docker compose exec api node prisma/seed.js

6Mises à jour

cd ~/sendprocolis/SendProColis-Web && git pull
cd ~/sendprocolis/SendProColis-Api && git pull
cd ~/sendprocolis/SendProColis-Web

docker compose build
docker compose up -d           # recrée uniquement ce qui a changé
docker image prune -f          # nettoie les anciennes images
🏗️
VITE_API_BASE_URL est figé au build du front. Un changement de DOMAIN impose docker compose build caddy (pas seulement un restart).

7Sauvegardes

Deux volumes portent des données précieuses : postgres-data et api-uploads (les certificats de caddy-data se régénèrent seuls).

# Dump base de données
docker compose exec -T postgres pg_dump -U sendprocolis sendprocolis | gzip > backup-$(date +%F).sql.gz

# Restauration
gunzip -c backup-2026-07-05.sql.gz | docker compose exec -T postgres psql -U sendprocolis sendprocolis

# Sauvegarde des fichiers uploadés
docker run --rm -v sendprocolis-web_api-uploads:/data -v "$PWD":/backup alpine \
  tar czf /backup/uploads-$(date +%F).tar.gz -C /data .
📦
Le nom du volume est préfixé par le dossier du projet (sendprocolis-web_). Vérifier avec docker volume ls.

8Commandes utiles

docker compose logs -f api        # logs API
docker compose logs -f caddy      # logs proxy / TLS
docker compose restart api        # redémarrer l'API
docker compose down               # arrêter (conserve les volumes/données)
docker compose exec postgres psql -U sendprocolis sendprocolis   # shell SQL

9Dépannage

SymptômeCause probableAction
Certificat TLS non émis DNS non propagé ou port 80/443 fermé dig sendprocolis.exemple.com, vérifier ufw, relire docker compose logs caddy
Front charge mais appels API en erreur réseau DOMAIN changé sans rebuild du front docker compose build caddy && docker compose up -d caddy
Images/audios uploadés cassés PUBLIC_BASE_URL incorrect doit valoir https://<DOMAIN> ; vérifier docker compose exec api env | grep PUBLIC
API redémarre en boucle Migration ou DATABASE_URL KO docker compose logs api ; vérifier que postgres est healthy
502 Bad Gateway API pas encore prête attendre le healthcheck postgres ; docker compose ps
